# Contributing

## What you need

A CUDA capable GPU is required to run the execution tests, the benchmarks and
the profiler. It is **not** required to build the project or to run the host
only unit tests, which cover configuration parsing, the snapshot format, the
smoothing kernels, the spatial hash and the initial condition generators. Tests
that need a device skip cleanly with the reason stated rather than failing, so a
run on a machine without one is honest rather than merely green.

Toolchain floors, all verified on the reference machine:

- CUDA Toolkit 13.3 or newer
- GCC 15 (nvcc 13.3 refuses anything newer)
- CMake 3.28 or newer
- Python 3 with matplotlib and tqdm for the figures
- TeX Live with latexmk, and poppler for `pdftotext`, for the reports

## Building

```bash
make setup
make build
```

`make setup` configures with fast math on. That switch reaches only the
benchmark library. The validation library is compiled from identical sources
with fast math forced off, so a physics gate can never be relaxed by a compiler
flag.

## Test levels

| level | target | needs a GPU | what it covers |
|---|---|---|---|
| unit, host | `make test-host` | no | formulas, parsing, snapshot format, initial conditions |
| unit, device | `ctest -L gpu` | yes | reductions, kernel parity across all variants |
| integration | `ctest -L gpu` | yes | 100 step smoke per solver, snapshot and resume bit identity |
| validation | `make validate` | yes | the physics gates |

Run everything with `make test`.

## Before opening a pull request

```bash
make check-style   # the dash gate, must be silent
make build         # warnings are errors, so a clean build is the gate
make test
```

## House rules

**No en dashes or em dashes anywhere.** Not in source, not in documentation, not
in the compiled PDFs. `scripts/check_no_dashes.py` enforces it and runs as part
of the report build. In LaTeX prose never type two hyphens: TeX turns them into
an en dash silently, and `\texttt` does not suppress it, only a verbatim region
does. Write ranges as "10 to 20".

**No number without a run.** Any performance figure in the documentation or the
reports must come from a file written by a program in this repository. The
figures and tables are generated by `scripts/plot_results.py` and
`scripts/gen_report_assets.py` from the recorded CSVs; nothing is typed by hand.
If you change a kernel, rerun `make bench` and regenerate.

**Physics gates are hard gates.** A failing conservation test is a stop the line
defect. Do not loosen a tolerance without a written justification in
`docs/ENGINEERING_LOG.md` explaining why the new value is the physically correct
bound.

**Express tolerances relative to a scale.** Never an absolute tolerance against
a quantity whose magnitude you have not stated. Use the magnitude of the value,
the machine epsilon, or a bound derived from the arithmetic.

**Zero warnings.** The build runs `-Wall -Wextra -Werror` and the nvcc
equivalents, so a successful build is the gate.

## Style

- `snake_case` for functions and files, `PascalCase` for types, `UPPER_SNAKE`
  for constants, a trailing underscore on private members.
- Kernels named by operation and variant, for example `compute_forces_tiled`.
- `.cu` and `.cuh` for device code, `.cpp` and `.hpp` for host code.
- Comments explain physics and constraints. A comment that restates the code is
  noise; a comment explaining why a barrier is where it is, or why a term is
  softened, is the point.

## Adding a benchmark point

`bench_all` skips configurations already present in the CSV, so a sweep can be
interrupted and resumed. Use `--force` to remeasure. Every row records the seed,
commit, CUDA runtime and driver versions, fast math setting and a timestamp, so
a number can always be traced back to the tree that produced it.

Compare only within a single session. Absolute timings move by around fifteen
percent with the thermal state of the card, while relative differences are
stable to a tenth of a percentage point.
